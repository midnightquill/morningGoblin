# Morning Goblin maintenance audit — 2026-10-24

Scope: dependencies, runtime helpers, Discord message and command handling, scheduling, catch-up, state persistence, tests, and the Windows watchdog. Preserve all existing features and saved attendance.

## Changes

- Updated Discord.js from locked version 14.25.1 to [14.27.0](https://github.com/discordjs/discord.js/releases/tag/14.27.0) and compatible transitive packages. The dependency audit initially reported five affected packages (three high, two moderate). The updated lockfile reports zero findings. Both direct dependencies, Discord.js and dotenv, are used; no new runtime dependencies were added.
- Memoized reply-to-bot checks per incoming message. Silence handling could inspect the same reference up to three times, including repeated failed requests. A weak-key cache shares the result without retaining message objects indefinitely.
- Fixed catch-up pagination when a scan's remaining allowance is less than 100 messages. Receiving the full requested page now correctly preserves the partial-scan indicator and resume cursor.
- Removed the unused `validateGuildVoicePack` helper; config reload already validates voice selections and restores invalid choices.
- Replaced the watchdog's fixed three-second startup sleep with a bounded wait for the launched child's lock. Existing logs showed startup failures even when the bot subsequently came online. Early process exit still fails promptly; Discord readiness remains a separate health check.
- Documented reproducible installs with `npm ci` and dependency auditing in the runbook.

## Validation

- Baseline: all 48 existing tests passed.
- All 49 tests passed after installing the updated lockfile with `npm ci --ignore-scripts`. Regression coverage checks capped history pages and shared reference lookups, including unavailable messages and silence requests.
- JavaScript and PowerShell syntax checks passed for the runtime and watchdog code. `git diff --check` passed.
- Offline integration tests use fake Discord channels and in-memory state; they never log in or send messages.
- Installed dependency audit: zero reported vulnerabilities.
- Posted departure and recovery notices in the configured live Discord morning channel. The watchdog restarted the bot successfully; the new process reported Discord readiness and a completed scheduler tick with no storage or runtime errors. A subsequent watchdog check confirmed it healthy.
- Compared saved state before and after the restart: both guilds and all 257 existing ledger filings were preserved. Scores, streaks, records, preferences, voice selections, and channel/timezone settings were unchanged.
- Private snapshots and maintenance-message receipts are retained under `data/backups/audit-2026-10-24/`, outside Git.

## Remaining maintenance opportunities

- `src/index.js` still combines several features. Further extraction of presence, conversation, and scheduler code is reasonable future work, but a broad rewrite adds regression risk to a quick maintenance pass.
- Attendance history intentionally remains durable. No ledger pruning, point recalculation, or deletion of legacy migration inputs was performed.
- Existing untracked profile-image variants are user assets and are not loaded by the bot. They were preserved.
- The windowless watchdog and periodic recovery remain appropriate for the existing Windows deployment. A deliberate restart still uses the watchdog's verified process stop; allow accepted work to save before restarting.
